# 时途产品升级路线图

> **状态：规划中，不代表功能已经上线。**
>
> **产品基线：v1.10.5（2026-11-27）。**
>
> 本文把此前的竞品调研和产品构想整理成可评审、可排期、可验收的升级方案。每个功能都说明「用户看到什么、怎样操作、需要什么数据、做到什么程度算完成」。

---

## 1. 产品方向

### 1.1 一句话定位

时途不是又一个待办清单，而是一个 **用真实时间检验计划** 的个人成长工具：

```text
人生目标 → 每周目标 → 今日任务 → 安排时间 / 专注执行 → 真实用时 → 每周复盘 → 调整下一轮计划
```

### 1.2 应该强化的独特优势

现有产品已经有六块有价值的基础：

1. **任务真实计时**：正计时、倒计时、暂停、多任务并行、独立时间记录。
2. **人生目标树**：长期方向可以逐层拆分。
3. **每周目标**：支持阶段打卡和次数打卡，不只是简单勾选。
4. **每日待办与月历**：分别解决「今天做什么」和「哪一天有约定」。
5. **闲时清单**：承接不急但想做的事，不与任务混在一起。
6. **可靠专注提醒**：45/5 循环、原生前台服务、响铃或仅振动。

升级的重点不是继续加页面，而是让这些模块 **产生关联、互相解释、形成反馈**。

### 1.3 三条产品原则

- **一个输入，多个视图**：同一件事录入一次，可以在今日、周计划、月历和目标树中查看。
- **计划与实际分开**：预计用时是用户的判断，实际用时来自计时记录；两者可以比较，但不能互相覆盖。
- **本地优先，智能可选**：核心功能断网可用；AI、云同步和共享功能必须由用户主动选择。

### 1.4 暂不做的事

- 不把八个 Tab 继续扩成十二个 Tab。
- 不强制所有用户使用时间块、习惯或番茄钟。
- 不把未完成任务做成连续打卡断签、扣分等惩罚机制。
- 不在没有账号体系和冲突合并方案前承诺实时多设备同步。
- 不默认上传任务标题、目标内容或生活记录。
- 不复制 Forest 的种树、Todoist 的复杂项目体系或 Sunsama 的订阅式 daily ritual。

## 2. 当前能力与真实缺口

下表以 v1.10.5 的代码为准，避免把已有能力误列为新功能。

| 模块 | 现在已经有的能力 | 升级前必须承认的缺口 | 主要代码 |
| --- | --- | --- | --- |
| 任务 | 正/倒计时、重复、截止提醒、时间记录、多任务并行 | 没有预计时长、计划时间段、目标关联、归档；删除会级联删除记录 | [task.dart](../lib/features/task/data/models/task.dart)、[task_repository.dart](../lib/features/task/data/repositories/task_repository.dart) |
| 每日待办 | 按日期和上午/下午/晚上分组的轻量清单 | 与任务库是两套数据，不能直接计时或携带目标关联 | [daily_task.dart](../lib/features/daily/data/models/daily_task.dart) |
| 每周目标 | 跨周访问、排序、普通/阶段/次数三种进度 | 没有预计投入、任务分解、人生目标关联和复盘 | [weekly_goal.dart](../lib/features/weekly/data/models/weekly_goal.dart) |
| 人生规划 | 无限层级目标树、手动进度 | 进度完全手动，不知道目标实际投入了多少时间 | [plan.dart](../lib/features/planning/data/models/plan.dart) |
| 统计 | 日/周/月总时长、热力图、饼图、任务明细 | 只按记录开始日期归集；跨午夜、暂停空档和时间来源无法精确解释 | [statistics_screen.dart](../lib/features/statistics/presentation/screens/statistics_screen.dart) |
| 专注 | 45/5、暂停、持续闹铃、仅振动、后台恢复 | 没有自定义预设、任务绑定、历史会话和长期专注统计 | [focus_timer_provider.dart](../lib/features/focus/providers/focus_timer_provider.dart) |
| 月历 | 自由文本标注、格内预览、当天面板 | 标注没有结构化时间、提醒或任务关联 | [calendar_note.dart](../lib/features/calendar/data/models/calendar_note.dart) |
| 闲时 | 标题、备注、试过/没试过和筛选 | 没有分类、时长估算、空闲推荐或转任务 | [leisure_item.dart](../lib/features/leisure/data/models/leisure_item.dart) |
| 同步 | WebDAV 手动全量备份/恢复、JSON 导入导出 | 只有一个 `backup.json`；没有备份历史、自动备份和冲突处理 | [sync_repository.dart](../lib/features/settings/repositories/sync_repository.dart) |
| 数据层 | JSON 文件、串行写入、临时文件替换、`.bak` 回退 | 新功能需要明确迁移版本和向后兼容规则 | [database_helper.dart](../lib/shared/database/database_helper.dart) |

### 2.1 两个容易做出错误数据的边界

#### 跨午夜与暂停

当前 `TaskRecord` 只有一条开始时间、结束时间和总时长。暂停期间的空档没有单独保存，因此不能可靠地回答：

- 昨晚 23:30 开始的 90 分钟，有多少属于今天？
- 一条 2 小时记录里，哪几个小时真正处于工作状态？
- 时间轴上的色块应该画在哪一段？

**结论：日时间轴、计划/实际对比和精细周报之前，必须先有「有效计时分段」。**

#### 专注与任务计时重复

当前任务计时和 45/5 专注是两套独立状态。若直接在两处都记时，同一段「做高数」会被统计两次。

**结论：专注绑定任务后，必须指定唯一时间来源。** 独立专注只进入专注统计；绑定任务的专注可以生成任务时间记录，但不能同时再累加一份重复时长。

## 3. 竞品启发与取舍

| 参考产品 | 值得借鉴的产品机制 | 时途的取舍 |
| --- | --- | --- |
| 滴答清单 | 多日历视图、番茄钟、习惯、倒数日、自然语言/语音收集 | 借鉴「快速收集 + 日历」，但模块入口保持克制，不把所有功能塞进首页 |
| Todoist | 快速捕获、项目/分区/标签/筛选、清晰优先级 | 先做一个统一收集箱和少量标签；复杂项目层级继续由人生目标树承担 |
| Forest | 专注成长反馈、标签、统计、共同专注、应用限制 | 借鉴动机反馈，但视觉采用时途自己的「时间轨迹」，不复制种树 |
| Toggl Track | 自动计时、时间表、项目报告、计划与实际对比 | 强化真实用时与偏差分析，不引入团队计费和工时审批 |
| Sunsama | 引导式每日规划、任务容量检查、时间盒、周复盘 | 把容量和周复盘做成轻量卡片，不要求每天完成冗长仪式 |

调研链接见文末。功能会变化，本表记录的是用于本次方案设计的机制，不代表对竞品当前价格的承诺。

## 4. 信息架构：先改首页，不增加 Tab

保留当前八个入口：**待办 / 每周 / 任务 / 统计 / 规划 / 闲时 / 月历 / 设置**。

建议的演进方式：

- **待办 → 今日**：从纯清单升级为「今日驾驶舱」，清单仍是默认视图。
- **每周**：从目标列表升级为「周计划 + 周末复盘」。
- **任务**：继续承担完整任务库、重复任务和计时详情。
- **统计**：从描述过去升级为解释偏差和给出下一轮建议。
- **规划**：从手动进度条升级为目标进展与实际投入。
- **闲时**：从仓库升级为「有合适空闲时间时，帮我挑一件」。
- **月历**：保留一句话标注，允许需要时升级为结构化日程。
- **设置**：集中管理备份、同步、隐私、专注和主题。

专注仍使用全局悬浮入口，不新增第九个 Tab。

### 今日页演进示意

```text
┌──────────────────────────────────────┐
│ 今日                  11月27日 周五   │
│ 可安排 6h40 · 已排 4h50 · 缓冲 1h50   │
├──────────────────────────────────────┤
│ [+ 说一句要做的事…]        [清单|时间轴]│
│                                      │
│ 09:00  高数复习              90分钟    │
│         [开始]  计划 09:00–10:30      │
│ ─────────────── 现在 ─────────────── │
│ 11:00  整理实验报告           45分钟    │
│                                      │
│ 未安排（3）                          │
│ · 背单词 20分钟                      │
│ · 给家里打电话 15分钟                │
└──────────────────────────────────────┘
```

默认仍显示用户熟悉的上午/下午/晚上分组；时间轴作为可切换视图，不强迫用户排满一天。

## 5. P0：新功能之前的数据地基

这些工作用户不一定直接看到，但决定了后续统计和同步是否可信。

### P0-01 建立唯一、可分段的时间记录

**用户效果**

- 23:30 开始、00:20 结束的记录，会按真实区间分别计入两天。
- 暂停 30 分钟不会出现在工作时间轴里。
- 同一段专注和任务计时不会重复累计。

**实现方向**

- 保留 `task_records` 作为一次计时会话的汇总。
- 新增 `time_segments`：保存每段有效开始、结束、时长、来源和所属记录。
- 来源至少区分 `task_timer`、`focus_session`、`manual`。
- 统计区间改为「与区间有交集，再裁剪交集」，不再只筛选开始时间。
- 老记录没有分段时，只能在迁移阶段按现有总时长生成近似分段，并标记为旧数据估算。

**验收标准**

- 跨午夜记录在两日之和等于原记录总时长，不丢秒、不重复。
- 暂停区间不计入工作时间。
- 同一任务同一时段被专注与任务计时绑定时，全库总时长只增加一次。
- 旧备份导入后统计不崩溃，旧记录有明确的兼容标记。

### P0-02 数据结构版本与无损迁移

**用户效果**

升级后原有任务、打卡、主题和计时不丢；旧备份仍可恢复。

**实现方向**

- 数据文件增加 `schema_version` 与 `exported_at`。
- 新字段一律可空或有默认值，不阻塞旧文件读取。
- 迁移按版本顺序执行，失败保留原文件和 `.bak`。
- 导入前展示版本、记录数量和缺失字段，不静默覆盖当前数据。

**验收标准**

- v1.10.5 备份可完整恢复到新版本。
- 连续跨越多个 schema 版本的测试备份可迁移。
- 迁移中断后再次启动，不产生重复记录或半迁移状态。

### P0-03 归档、删除与历史快照

**用户效果**

完成任务后可以归档，但历史图表仍显示当时的任务名称；删除不再让一段历史凭空消失。

**实现方向**

- 任务增加 `archived_at`、`deleted_at`。
- 默认操作从「归档」开始，物理删除放进二次确认的高级入口。
- 时间记录保存任务标题快照。
- 同步需要删除墓碑，避免另一台设备把已删除数据恢复回来。

**验收标准**

- 归档任务不再出现在日常列表，但仍可筛选历史。
- 改名后旧记录可显示「当时的名称」。
- 删除确认明确说明是否同时删除时间记录。

### P0-04 目标关联模型

**用户效果**

一件事可以明确属于哪个每周目标或人生目标，但不会强迫所有临时待办都有关联。

**实现方向**

- `tasks` 增加可空 `plan_id`、`weekly_goal_id`。
- `daily_tasks` 增加可空 `task_id`，允许轻量待办升级为完整任务。
- `weekly_goals` 增加可空 `plan_id` 和预计投入。
- 打卡点与任务的关联使用独立链接表，避免把大段嵌套数据塞进单个 JSON 行。

**验收标准**

- 无关联的旧任务行为完全不变。
- 一个任务不重复计入两个周目标或两个人生目标。
- 删除关联只移除链接，不删除任务或历史记录。

### P0-05 凭据与隐私保护

**用户效果**

WebDAV 密码不继续以明文 JSON 形式保存；AI 和云功能有关闭入口。

**实现方向**

- Android 使用系统安全存储保存 WebDAV 密码，旧值首次读取后迁移。
- 备份文件继续排除密码。
- 任何未来云端 AI 请求都显示发送范围，并提供本地/禁用选项。

**验收标准**

- 新备份中不包含密码。
- 卸载或换机后清楚提示需要重新配置凭据。
- 关闭智能功能后，不产生相应网络请求。

## 6. v1.11：今日执行中心

**目标：让用户打开 App 后，30 秒内知道今天做什么，并能把事情安排下去。**

### R01 今日容量卡

**用户看到的效果**

首页刊头下方增加一张紧凑卡片：

```text
今天可安排 6 小时 40 分钟
已安排 4 小时 50 分钟 · 还剩 1 小时 50 分钟
[设置可用时间]
```

可安排时间 = 用户设置的可用时段 − 固定日程 − 缓冲。没有设置时显示「尚未设置可用时间」，不擅自假设 8 小时工作制。

**交互**

- 点击卡片设置起床/睡觉时间或可用起止时间。
- 可设置每日缓冲，例如 20%。
- 超排时用警示色提示「超出 50 分钟」，不阻止保存。

**数据依赖**：用户设置、`calendar_events`、任务预计时长。

**验收标准**

- 空计划、超排、跨午夜固定日程都显示正确。
- 卡片在 320dp 窄屏不溢出，文字可随系统字体放大。

### R02 一句话快速收集

**用户看到的效果**

输入框提示「例如：明天下午 3 点复习高数 90 分钟」。保存前显示可编辑的结构化预览：

```text
标题：复习高数
日期：明天 15:00
预计：90 分钟
存入：任务库
```

**交互**

- 第一版使用本地日期、时间和时长规则解析，不依赖 AI。
- 用户可点击每个预览字段修改。
- 选择「今天做」写入今日待办；选择「以后做」写入任务库。
- 解析失败时原样保存标题，不阻止收集。

**数据依赖**：任务预计时长、计划开始时间。

**验收标准**

- 支持今天/明天/下周、上午/下午/晚上、常见相对时间和「90 分钟/1.5 小时」。
- 不自动创建用户没确认的日期或重复规则。
- 从打开输入框到保存，常规输入不超过 20 秒。

### R03 任务关联每周目标和人生目标

**用户看到的效果**

任务详情出现「关联目标」：

```text
本周目标：完成高数第 3 章
人生目标：通过研究生考试
```

列表行显示一个小目标标记；进入目标树后，可以反向看到关联任务和累计真实用时。

**交互**

- 创建或编辑任务时选择，可跳过。
- 每周目标可以选择一个父级人生目标。
- 人生目标提供「手动 / 子目标汇总 / 关联任务汇总」三种进度来源，默认保持手动，避免升级后旧目标进度突变。

**验收标准**

- 周完成度仍按现有打卡点加权，不因关联任务重复计算。
- 人生目标自动汇总时，显示计算依据和排除项。

### R04 预计用时与任务分解

**用户看到的效果**

任务从「一个标题」变成可估算的行动：

```text
完成高数第 3 章                  预计 4 小时
├─ 看完概念                90 分钟  [ ]
├─ 完成例题               120 分钟  [ ]
└─ 整理错题                90 分钟  [ ]
```

子任务可以只是清单项，也可以升级为独立计时任务。

**交互**

- 编辑时填写 5 分钟～7 天的预计时长。
- 长按或更多菜单选择「拆成步骤」。
- 父任务预计时长可由子项自动汇总，也可手动锁定。

**验收标准**

- 有预计时长的任务才能进入容量计算。
- 子任务开始计时不自动把父任务也设为计时中。

## 7. v1.11.1：日时间轴与计划/实际

**目标：让「计划 2 小时，实际 40 分钟」变得一眼可见。**

### R05 日时间轴

**用户看到的效果**

今日页切换到时间轴后，按小时显示任务卡片；卡片长度代表预计时长。当前时间有一条细线。正在计时时卡片边缘出现呼吸式进度描边。

**交互**

- 拖动卡片调整开始时间，以 15 分钟吸附。
- 拖动下缘改变预计时长。
- 点击空白时段快速添加任务。
- 发生重叠时显示「与高数复习重叠 30 分钟」，可自动顺延或保留。
- 不适应时间轴的用户始终可以切回清单。

**数据依赖**：P0-01、任务预计时长和开始时间。

**验收标准**

- 0 秒、极短任务、跨午夜任务不会画出负宽度。
- 拖动后立即保存，失败回滚。
- 遵循系统「减弱动效」设置，不使用连续振动。

### R06 计划/实际偏差

**用户看到的效果**

任务行和统计页出现比较：

```text
高数复习
计划 1小时30分 · 实际 45分钟 · 少用 45分钟
```

时间轴上，计划用浅色底框，真实有效计时用实色块覆盖。

**交互**

- 点击偏差进入该任务的记录明细。
- 复盘时可选择原因：估时偏长、临时中断、任务取消、专注不足、其他。
- 偏差只作为反馈，不自动判定用户效率高低。

**数据依赖**：唯一时间来源、有效分段、任务预计时长。

**验收标准**

- 多个并行任务的「实际总时长」可以大于一天自然时长，页面明确标注这是累计投入。

## 15. 数据模型建议总表

| 数据 | 建议变化 | 目的 |
| --- | --- | --- |
| `tasks` | `estimated_seconds`、`planned_start`、`plan_id`、`weekly_goal_id`、`priority`、`archived_at`、`deleted_at` | 计划、关联、归档 |
| `task_records` | 保留汇总字段，增加来源与任务标题快照 | 历史可解释 |
| `time_segments` | 新表：记录有效开始/结束、来源、所属会话 | 跨日、暂停、时间轴、防重复 |
| `daily_tasks` | 可空 `task_id`、`estimated_seconds` | 轻量待办可升级为任务 |
| `weekly_goals` | `plan_id`、`estimated_seconds`、复盘引用 | 目标关联与周计划 |
| `plans` | `progress_mode`、`target_date`、权重、排序 | 手动/自动进度 |
| `weekly_milestone_links` | 新表：打卡点与任务关联 | 分段目标落实到行动 |
| `focus_sessions` | 新表：任务/目标、标签、起止、状态、轮次、备注 | 专注历史与结算 |
| `calendar_events` | 新表：开始/结束、全天、提醒、关联任务 | 结构化日程 |
| `calendar_notes` | 保持现有自由文本模型 | 向后兼容 |
| `habits` / `habit_checkins` | 新表：频率、替代动作、完成/跳过/补记 | 弹性习惯 |
| `leisure_items` | 分类、预计时长、偏好 | 空闲推荐 |
| `templates` / `template_items` | 新表：场景模板和相对日期规则 | 批量创建 |
| 数据根节点 | `schema_version`、`exported_at` | 迁移和备份识别 |
| 同步元数据 | 设备 ID、版本号、删除墓碑、基础快照版本 | 后续安全合并 |

### 必须遵守的统计口径

1. **任务实际用时**只认可有效时间分段，不使用任务详情里手填数字替代。
2. **专注时长**与**任务实际时长**可展示同一事实的两个视角，但全库累计不能重复。
3. **完成数量**按完成事件去重，不按列表行数猜测。
4. **并行任务投入**允许累计超过一天自然时长，页面标注为「累计投入」。
5. **计划偏差** = 实际有效时长 − 预计时长；没有预计值时不显示偏差。
6. **跨日统计**按有效区间裁剪，老数据估算必须可识别。

## 16. 交互与视觉约束

时途已有陶土暖笺、简洁、可爱、科技共十套主题。新功能应复用现有设计系统，而不是另起一套视觉。

- 使用现有 `PaperCard`、`PaperButton`、`Masthead`、`SegmentedControl`、`ThemeExtension<AppDesign>`。
- 点击反馈沿用 `PressableScale` 与 `AppHaptics`；不恢复导航振动。
- 深色主题所有弹窗、时间轴、图表和输入框继承当前主题。
- 触控目标不小于 44dp；关键信息不只靠颜色表达。
- 支持系统字体放大和「减弱动效」。
- 动效用于说明状态变化，不做无意义的持续漂浮。
- 新页面首屏优先展示内容和下一步动作，刊头信息继续克制。

## 17. 每个版本的验收清单

### 功能验收

-  golden path 可以从入口完整走到结果，失败有明确提示。
- 空状态、加载失败、保存失败、权限拒绝、进程恢复均有对应界面。
- 新增数据可备份、可恢复、可重复导入且不重复。

### 数据验收

- 跨日、跨周、跨月、闰年和夏令时边界有自动化测试。
- 并发启动/停止、快速切换页面、编辑中删除有代际或事务保护。
- 统计结果能下钻到记录，用户能理解数字怎样得出。

### 发布验收

- `flutter analyze` 无新增问题。
- 全量测试与 golden 截图通过。
- 至少覆盖 320dp 窄屏、常规屏和深色主题。
- Android 后台、锁屏、通知操作、时区变化做真机验证。
- 版本号、README、Release APK 和 SHA-1 一致。
- 不提交凭据、`.zcode/`、临时文件或未经确认的用户数据。

## 18. 怎样判断升级有效

目前没有默认埋点，不应为了做增长指标偷偷上传数据。可以先采用本地、可选的使用统计和用户反馈。

以下是**建议目标，不是当前实测值**：

| 指标 | 建议目标 | 测量方式 |
| --- | --- | --- |
| 快速收集 | 常规输入 20 秒内完成保存 | 可用性测试 |
| 首次今日规划 | 新用户 2 分钟内安排第一件事 | 可用性测试 |
| 时间数据可信度 | 重复计时测试中重复时长为 0 | 自动化测试 |
| 周复盘完成 | 愿意在一周后回看复盘并调整计划 | 可选本地反馈 |
| 备份可靠性 | 恢复后核心表数量一致、凭据不导出 | 自动化与真机测试 |
| 主题可读性 | 所有新页面通过现有对比度规则 | golden 与 tokens 测试 |

如果用户只是需要简单清单，容量卡、时间轴和复盘都应该可以隐藏，不能把高级流程变成使用门槛。

## 19. 更长期的想法池

以下想法保留，但在 v1.16 前不建议启动：

1. **共同专注房间**：好友在线陪伴，需要账号、在线状态和内容安全方案。
2. **共享目标与家庭日历**：涉及权限边界、冲突合并和隐私。
3. **Web/桌面端**：先证明手机核心闭环成立，再复用同步协议。
4. **穿戴设备**：手表开始专注、查看下一项，需要单独平台适配。
5. **年度人生地图**：把目标、事件和时间投入放到同一张年视图。
6. **精力日记**：记录睡眠、精力和情绪，仅做相关性参考，不做健康诊断。
7. **专注场景包**：学习、写作、运动等不同预设、声音和复盘问题。
8. **智能提醒降噪**：根据用户响应减少低价值提醒，必须可解释和关闭。
9. **成就与里程碑**：强调完成和探索，不设置断签惩罚。
10. **开放自动化**：例如「专注完成后自动记录进度」，先提供有限、透明的内置动作。

## 20. 最近三次迭代建议

如果只选下一步，不建议同时启动全部路线。推荐顺序：

1. **v1.11.0 今日执行中心**：快速收集、预计时长、容量卡、目标关联。
2. **v1.11.1 时间可信度**：有效分段、日时间轴、计划/实际偏差。
3. **v1.12.0 周闭环**：周计划、复盘、目标回写。

这三步完成后，时途会从「多个时间管理工具的集合」变成「能解释时间花在哪里、下一轮怎样调整的个人规划系统」。
